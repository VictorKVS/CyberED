# ALINA / FATHER — алгоритм инженерного аудита ИБ v0.1

## Правила
Аудит проводится только при документально подтверждённых полномочиях, согласованном периметре и правилах тестирования. Режимы: Passive (документы/интервью), Safe (конфигурации/контролируемые проверки), VA (авторизованное сканирование), Active (только отдельное письменное разрешение). Критичные системы — без воздействия по умолчанию.

## Шаги, входы, результаты и контроль качества
| Этап | Вход | Действия | Выход | Критерий завершения |
|---|---|---|---|---|
| 00. Мандат | запрос, владелец | цель, полномочия, ограничения, согласование тестов | Audit Charter, Rules of Engagement | утверждённый периметр |
| 01. Обследование | анкеты, интервью | инвентаризация активов, владельцев, данных, интерфейсов | реестр активов и данных | владельцы и границы указаны |
| 02. Архитектура | конфигурации, схемы | OSI L1–L7, зоны, доверие, потоки, гипервизоры, облака | схема, DFD, карта потоков | каждый критичный поток прослежен |
| 03. Классификация | реестр данных и функций | определить ИСПДн, ГИС, КИИ и другие профили; уровни/категории только по критериям | паспорт системы | основания классификации сохранены |
| 04. Нормативная карта | паспорт, редакции актов | выбрать применимые нормы; точные пункты, исключения и сроки | requirements register | каждое требование имеет ссылку и редакцию |
| 05. Угрозы | активы, нарушители | методика ФСТЭК 2021, БДУ, сценарии, последствия, актуальность | модель угроз, сценарии | обоснование каждой актуальной угрозы |
| 06. Меры | требования, угрозы | сопоставить меры, компенсирующие решения и остаточные пробелы | control matrix | есть владелец и статус каждой меры |
| 07. СЗИ | меры, спецификации | проверить продукт, версию, сертификат ФСТЭК/ФСБ, срок, область, ограничения | реестр СЗИ и сертификатов | подтверждены применимые сведения |
| 08. Проверки | согласованные правила | Passive → Safe → VA → Active только по разрешению; тесты Top-100 как внутренний чеклист | протоколы, доказательства | результаты воспроизводимы |
| 09. Риски | результаты тестов | последствия, вероятность/реализуемость, приоритет | реестр рисков | методика оценки указана |
| 10. Исправление | риски и пробелы | мероприятия, ответственные, сроки, бюджет, контроль | план устранения | решения и сроки согласованы |
| 11. Ретест | план устранения | повторные проверки и подтверждение | итоговый отчёт и акт | доказательства сохранены, остаточные риски приняты владельцем |

## Модель данных для агента
`audit_id, system_id, scope, permission_id, asset_id, data_flow_id, osi_layer, regulation_id, edition, clause, applicability_reason, requirement_id, threat_id, bdu_id, scenario_id, control_id, product_id, certificate_id, test_id, top100_id, evidence_id, finding_id, risk_id, remediation_id, reviewer, verified_at, status`.

## Формат несоответствия
ID; актив; требование/пункт; фактическое состояние; ожидаемое состояние; сценарий угрозы; риск; доказательство; рекомендация; владелец; срок; ретест; статус. Не подменять отсутствие данных утверждением о несоответствии: статус «не проверено».

## Нормативная развилка
- ИСПДн: 152-ФЗ, ПП №1119, приказ ФСТЭК №21; при применении СКЗИ — акты ФСБ по применимости.
- ГИС и иные охватываемые системы: приказ ФСТЭК №117 (2025) с действующими изменениями; приказ №17 — исторический.
- Значимые объекты КИИ: 187-ФЗ, приказы ФСТЭК №235 и №239; иные применимые требования.
- Роспотребнадзор — условия труда/эксплуатации, вне OSI; Роскомнадзор — контроль ПДн.

## Принцип оценки
Статусы: NOT_APPLICABLE (обоснованно), UNKNOWN (нет данных), PASS (доказано), FAIL (доказано), PARTIAL (частично), NOT_TESTED (не проверено). Сводная оценка не может считать UNKNOWN или NOT_TESTED успешными. Результат не равен официальной аттестации системы.
