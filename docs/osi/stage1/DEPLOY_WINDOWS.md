# Развёртывание CyberED Security Engineering — Windows 11

## Безопасный запуск
**Важно:** существующий каталог `G:\1\CyberED -IB` не перезаписывается. Скрипт не удаляет файлы, не переключает ветки автоматически в существующем Git-репозитории и не делает `git reset`.

В PowerShell:
```powershell
# Если CyberED уже клонирован в G:\1\CyberED -IB:
git -C 'G:\1\CyberED -IB' status
git -C 'G:\1\CyberED -IB' fetch origin feature/osi-security-atlas-ru
# При чистом рабочем дереве вручную перейти на нужную ветку:
git -C 'G:\1\CyberED -IB' switch feature/osi-security-atlas-ru
# Запустить из корня репозитория:
& 'G:\1\CyberED -IB\docs\osi\stage1\START_CYBERED.ps1'
```
Если каталога нет, скрипт можно запустить из скачанного файла с параметром `-Root 'G:\1\CyberED -IB'`; он клонирует репозиторий. Для изолированного нового клона можно выбрать `-Root 'G:\1\CyberED-Stage1'`.

После запуска открыть **http://127.0.0.1:8088/portal.html**. Сервер привязан к 127.0.0.1 и не должен быть открыт в Интернет.

## Проверки
```powershell
python 'G:\1\CyberED -IB\docs\osi\stage1\smoke_test.py' --root 'G:\1\CyberED -IB\docs\osi\stage1'
python 'G:\1\CyberED -IB\docs\osi\stage1\alina_ib_agent.py' 'G:\1\CyberED -IB\docs\osi\stage1\example_system.json' -o 'G:\1\CyberED -IB\docs\osi\stage1\audit_plan.json'
```
Проверить вручную: 10 разделов, 8 уроков, 7 уровней OSI, 100 проверок, добавление узла, экспорт JSON, формирование плана, добавление доказательства. Данные браузера сохраняются в localStorage.

## План прокачки
P0: воспроизводимый запуск, тесты и устранение дефектов.
P1: серверный FastAPI, PostgreSQL, роли студента/преподавателя/аудитора, журнал действий.
P2: нормативная база по версиям и точным пунктам, источники ФСТЭК/ФСБ/ГОСТ, граф требований.
P3: БДУ, угрозы, Top-100, привязка к активам и OSI.
P4: архитектурный редактор с настоящими DFD и границами доверия.
P5: каталог СЗИ, сертификаты и техническая совместимость.
P6: Алина LLM/RAG с цитированием, тестами качества и запретом недоказанных утверждений.
P7: лабораторные задания, оценки, отчёты, экспорт документов, интеграционные испытания.

## Ограничения
Smoke-тесты не заменяют браузерные испытания. Планировщик аудита работает без LLM и не проводит сетевых проверок. Сайт и Python-агент пока два отдельных компонента, API между ними ещё нет.
