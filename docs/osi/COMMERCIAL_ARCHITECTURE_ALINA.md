# CyberED — Senior Web Architect / коммерческий продукт / AI-консультант Алина

Версия 0.1. Статус: проектный документ и первый автономный интерфейс консультанта. Коммерческий спрос не подтверждён.

## Продуктовая гипотеза
**B2C**: начинающие/действующие инженеры ИБ — практические курсы и портфолио. **B2B**: небольшие ИБ-команды — инструменты обследования, архитектуры и подготовки аудита с проверяемыми источниками. Не обещать сертификацию, гарантированное трудоустройство или автоматическое соответствие ФСТЭК.

## Воронка
1. Landing: ценностное предложение и демонстрация рабочего результата.
2. AI-консультант: выясняет роль, задачу и профиль, рекомендует подходящий сценарий.
3. Интерактивное демо: урок, архитектура, план аудита.
4. CTA: «Начать бесплатно» и «Запросить пилот» (только после подключения реальной формы).
5. Оплата и личный кабинет — после проверки спроса и подключения платёжного провайдера.
6. Обучение: диагностика → маршрут → практика → проверка → портфолио.
7. B2B: пилот на обезличенной тестовой системе, согласование объёма и ограничений.

## Агент Senior Web Architect
Роль: продуктовый архитектор и техлид; подотчётен владельцу CyberED/FATHER.
Вход: потребности пользователя, продуктовые метрики, репозиторий, дизайн-система, требования ИБ, бюджет.
Выход: PRD, user journeys, дизайн-токены, API contracts, backlog, ADR, план экспериментов, QA-отчёты.
Критерии: доступность WCAG, Core Web Vitals, mobile-first, безопасность, privacy by design, доказанная работоспособность, отсутствие вымышленных маркетинговых утверждений.
Нельзя: выдавать гипотезы спроса за факты, подключать сбор персональных данных без согласованного процесса, обещать действующую оплату без интеграции.

## Алина: три режима
- **Sales**: приветствие, квалификация интереса, сценарий демо, CTA; никаких фиктивных скидок и «последних мест».
- **Tutor**: объяснение тем, задания, обратная связь с ссылками на источники.
- **Engineer**: подготовка плана обследования/аудита, архитектуры и контрольных мер с доказательствами.
На первой итерации консультант работает локально по сценариям, без LLM, без отправки данных на сервер и без голосового/видеоаватара. Это не реальный диалоговый ИИ.

## Нефункциональные требования
- Защита ПДн, согласие на обработку при будущих формах, минимизация данных, retention policy.
- Защита от prompt injection, RAG grounding, проверка цитат, human-in-the-loop для нормативных заключений.
- Раздельные роли student/teacher/auditor/admin; RBAC, audit trail, rate limits, мониторинг.
- Аватар не должен вводить в заблуждение относительно своей природы; явно обозначать цифрового помощника.
- Никаких секретов, реальных медицинских данных или активного сканирования в демо.

## Метрики проверки рынка
CTR CTA; доля посетителей, запустивших демо; завершение первого урока; запросы пилота; платная конверсия после подключения оплаты; удержание; доля успешных практических работ. Не заявлять результаты до измерений.

## Дорожная карта
P0: landing + виджет Алины + сценарий входа + ручной smoke QA.
P1: интервью 10–15 потенциальных пользователей, 2–3 пилотных организации, корректировка оффера.
P2: FastAPI, PostgreSQL, аккаунты, серверные сессии, аналитика с учётом согласий.
P3: LLM/RAG Алина с источниками, guardrails, evaluation.
P4: видеоаватар (только при измеримой пользе и приемлемой стоимости), голос/субтитры, fallback на текст.
P5: тарифы, юридические документы, платежи, возвраты, поддержка — после коммерческой валидации.

## Definition of Done
Сквозной путь посетитель → консультант → демо → действие проверен в браузере, с мобильного, без вымышленных функций. Ни один модуль не готов без испытаний.
